## Akzeptanzkriterien (Spec §0, §3, §4)

- [ ] A1 Alle 14 Pflicht-Tools registriert, Namen und Felder exakt wie §4 (`tools/list`).
- [ ] A2 IDE-Loop end-to-end per echtem MCP-Client: open_editor → skeleton → inspect → mutate → vision → save → reload (e2e/mcp-smoke.ts).
- [ ] A3 Mutation läuft über `$e.run` im Nutzer-Tab; genau ein History-Eintrag „Agent: <label>" pro mutate_canvas (Strg+Z-Freundlichkeit).
- [ ] A4 Kein Schreiben an `_elementor_data` außerhalb des Editors (wp_rest-Beschreibung + Code).

## Fehlerpfade (Spec §5)

- [ ] F1 Kein Browser/Tab → `not_connected`/`no_editor_tab` mit Hinweis, kein Absturz; `canvas_status` wirft nie.
- [ ] F2 Unbekannte ID in Op → `element_not_found`, restliche Ops laufen, History-Gruppe wird geschlossen.
- [ ] F3 Ungültige Op (widget ohne widgetType, unbekannter Key) → Tool-Fehler mit Pfad.
- [ ] F4 Atomic-Element: Create geht; Settings-Fehler → `unsupported_atomic` oder klarer editor_error.
- [ ] F5 Save-Fehler → `{ok:false,error}` statt Exception.

## Edge Cases

- [ ] E1 Geometrie direkt nach Create (Render asynchron) → Höhe > 0 dank Render-Wait.
- [ ] E2 Reload/Navigation → Overlay wird neu injiziert (addInitScript), Events laufen weiter.
- [ ] E3 maxDepth im Skelett; Responsive-Duplikate und `__dynamic__` werden entfernt.
- [ ] E4 Screenshot ohne id = ganzer Preview-Viewport; Clip auf Viewport geklemmt.
